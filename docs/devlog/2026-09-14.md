# 2026-09-14 JD to Notion Development Log

## Work Summary

담당자가 요청글에 잘못된 학위명을 적은 경우 공식 과정 URL의 학위가 Proposed Notion Major name에 반영되지 않던 정책을 변경했다. 동시에 Proposed 입력이 자동 계산 원본과 연결되어 Delete나 직접 수정이 즉시 되돌아가던 문제를 해결했다.

## Work Completed

- URL 경로에서 독립된 학위 토큰이 하나만 확인되면 요청글 학위보다 우선해 Proposed 이름과 Major 검색 키를 계산하도록 변경했다.
- 요청글 원문은 보존하고, 요청글과 URL 학위가 다르면 어떤 값이 URL 기준으로 보정됐는지 화면에 표시하도록 했다.
- `notionMajorNameOverride`를 추가해 직접 수정값을 자동 계산값과 분리하고, 서버의 Notion 미리보기까지 전달되도록 연결했다.
- Proposed 입력 중 카드 전체를 다시 렌더링하지 않고 제목·상태·안내만 갱신해 Delete와 연속 입력이 끊기지 않도록 했다.
- Birmingham, Manchester, Nottingham 실제 요청 형식과 직접 수정·삭제 동작을 Node 및 Playwright 회귀 테스트에 추가했다.
- Playwright의 입학 사이클을 fixture 기대값인 `2026/27`로 고정해 로컬 `.env`와 무관하게 브라우저 회귀가 재현되도록 했다.

## Decisions

- 학위 정보의 우선순위는 `사용자가 Proposed에 직접 입력한 값 > URL 경로의 단일 학위 토큰 > 요청글 학위`로 정했다.
- URL에서는 학위 토큰만 사용하고 전체 학과명은 추측하지 않는다. 복수 학위 토큰이나 학위 확인 불가는 기존처럼 수동 검토 대상으로 남긴다.
- 직접 입력한 Proposed 이름도 기존 Notion 표기 규칙에 맞게 인식 가능한 선행 학위명을 뒤로 정규화하지만, 학위명을 완전히 지운 값은 자동으로 복원하지 않는다.
- 원문 필드를 수정값으로 덮지 않아 담당자 작성 내용과 자동·수동 보정 결과를 계속 구분할 수 있게 했다.

## Work Summary - SOP 자동 다운로드 중복 방지

JANDI 첨부파일 자동 다운로드가 한 번의 요청에서 두 번 실행되는 현상을 조사하고, 첫 클릭의 실제 다운로드 시작 여부와 중복 요청을 모두 확인해 한 파일만 내려받도록 수정했다.

## Work Completed - SOP 자동 다운로드 중복 방지

- 관련 코드의 마지막 변경은 9월 2일이었고 JANDI 실행 파일은 9월 4일 업데이트된 것을 확인했다. `.env`의 `JANDI_DOWNLOAD_DIR`은 기존처럼 바탕화면을 가리키며 클릭 횟수에는 관여하지 않았다.
- JANDI 첨부파일을 첫 번째로 클릭한 뒤 다운로드 폴더에서 대상 파일이나 임시 다운로드 파일의 생성·변경을 최대 2초 동안 감지하도록 했다.
- 첫 클릭으로 다운로드가 시작된 경우 기존 뷰어의 다운로드 버튼을 다시 누르지 않도록 했고, 다운로드 활동이 없을 때만 기존 보조 클릭을 실행하도록 했다.
- 동일한 SOP 자동 다운로드 arm 요청과 JANDI 첨부파일 실행 요청이 5초 안에 중복으로 들어오면 기존 요청을 재사용하도록 서버 측 중복 방지를 추가했다.
- 다운로드 폴더 경로를 JANDI CDP 보조 스크립트에 전달하고, 중복 arm 및 trigger 회귀 테스트를 추가했다.

## Decisions - SOP 자동 다운로드 중복 방지

- 두 번째 파일을 내려받은 뒤 삭제하는 방식 대신, 다운로드 시작 증거를 확인해 두 번째 클릭 자체를 막는다.
- JANDI 버전에 따라 첫 클릭이 미리보기만 여는 경우도 지원해야 하므로 기존 뷰어 다운로드 보조 경로는 유지하되 파일 시스템 활동이 없을 때만 사용한다.
- UI나 API에서 같은 요청이 빠르게 반복되는 경우까지 막기 위해 5초의 짧은 중복 억제 구간을 둔다. 정상적인 수동 재시도는 이 시간이 지난 뒤 가능하다.
