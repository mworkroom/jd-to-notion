## Decisions - 요청 검토 패널 분리

- request state 자체는 workflow 조정자인 `app.js`에 유지하고, 패널은 `getContext()`로 현재 객체를 받아 검토 UI 편집만 담당한다. Notion·Word·SOP 연동 무효화는 앱 callback에서 계속 조정한다.
- 요청 변경 callback은 일반 입력 변경과 SOP 옵션 변경 두 종류로 제한했다. 패널이 외부 컨트롤러를 직접 알지 않도록 해 Notion·Word·다운로드 의존성이 검토 UI로 역류하지 않게 했다.
- 현재 346줄의 `app.js`에는 분석 시작, 섹션 표시, 패널 연결, 파생 출력 조정이 남아 있어 애플리케이션 진입점으로 적절하다. 파생 출력까지 별도 모듈로 옮기면 여러 패널 callback이 늘어나는 반면 독립 상태나 I/O가 없어, 이번 단계에서 구조 분리는 사실상 종료하는 편이 낫다고 판단했다.
