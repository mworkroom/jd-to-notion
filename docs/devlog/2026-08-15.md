# 2026-08-15 Admission Guidelines Automation Development Log

## Work Summary

기존 입학요강 자동화에 SOP 감수 요청을 추가하기 위한 구현 계획을 확정했다. SOP 파일을 열어 언어와 기준 학교를 확인하는 작업은 유지하되, 담당자·학생·차수 추출과 기존 학교·학과 관계 선택, Notion Work Log 생성을 자동화하여 반복 입력을 줄이는 방향이다.

## Work Completed

- `docs/spec/SOP_AUTOMATION_PLAN.md`를 작성했다.
- SOP 요청 판별, 차수 추출, 영문 기본값, Student·Agent 매칭 규칙을 문서화했다.
- `입학 요강 1`의 Major를 학교·학과 기본값으로 사용하고, 틀린 경우에만 후보 목록을 펼쳐 변경하는 UI를 확정했다.
- 기존 번호 누락 Work Log에 대한 fallback과 생성일 기반 추측 제외 원칙을 기록했다.
- SOP Work Log의 Notion 속성 매핑, 중복 방지, 오류 처리, 테스트, controlled live 절차를 정리했다.
- live Notion을 읽기 전용으로 조사한 후보 포함률, 기본값 적중률, 입학요강 번호 상태를 계획의 근거로 포함했다.

## Decisions

- 과거 Notion Automation이 앱이 저장한 번호 제목을 덮어쓰므로 해당 Automation은 J가 비활성화한다. 이후 Work Log 제목은 앱이 직접 저장한다.
- 학교와 학과는 별도 값으로 조합하지 않고 기존 Major relation 하나를 선택한다. University는 Major에서, Agent는 Student에서 rollup한다.
- `입학 요강 1`은 자동 확정이 아니라 기본 선택으로 사용한다. 기본값이 틀리면 생성 전에 `변경`에서 다른 기존 Major를 선택한다.
- Make.com은 하루 한 번 수동 실행하는 현재 운영을 유지하며 이번 구현에서 수정하지 않는다.
- Student 또는 Major 후보를 확정할 수 없는 예외는 첫 버전에서 억지로 추론하지 않고 수동 처리한다.

## Current Status

SOP 자동화는 구현 전이며 계획과 범위만 확정됐다. 코드, UI, Notion 데이터, Notion Automation, Make.com 설정은 변경하지 않았다.

- 계획의 Phase SOP-1부터 순서대로 구현한다.

## Work Summary - SOP 감수 요청 자동화 구현

확정된 SOP 자동화 계획에 따라 JANDI 요청 판별부터 기존 Notion 관계 선택, Work Log 생성 준비까지 구현했다. 기존 입학요강 흐름은 그대로 유지하고 SOP 요청일 때만 별도 입력·미리보기·생성 규칙을 사용한다.

## Work Completed - SOP 감수 요청 자동화 구현

- `SOP`와 `감수` 키워드로 요청 유형을 판별하고, 명시되지 않은 회차는 1차, 언어는 영문으로 기본 처리했다.
- 2차·3차를 인식하고 복수 회차 또는 4차 이상은 생성 전에 차단하도록 검증했다.
- SOP 화면에서는 입학요강 학과 입력, 최종 출력, Word 생성 영역을 숨기고 회차·언어·학교·학과 선택 영역을 표시했다.
- 기존 Student와 담당 Agent 연결을 확인한 뒤 해당 Student의 `입학 요강` Work Log에 연결된 Major만 후보로 조회하도록 구현했다.
- `입학 요강 1`, 번호 없는 첫 요강, 유일 후보 순으로 기본 Major를 정하고 생성일 기준 추측은 사용하지 않았다.
- 기본 학교·학과는 한 줄로 표시하고 `변경`을 누를 때만 다른 기존 후보를 펼치도록 구현했다.
- `SOP n차 감수(영문/국문)` 제목, SOP Category, 평일 기준 이틀 뒤 마감일, `2026/27` 시즌으로 Work Log 한 건만 생성하도록 연결했다.
- SOP 중복 방지 fingerprint에 요청 유형, 학생, 회차, 언어, Major를 포함하고 생성 직후 제목 재저장·검증 및 journal 복구 흐름을 유지했다.
- SOP 규칙, 담당 Agent 불일치 차단, 후보 선택, 단일 Work Log 생성 테스트를 추가하고 전체 104개 테스트를 통과했다.

## Decisions - SOP 감수 요청 자동화 구현

- 첫 버전은 기존 Student와 기존 Major만 재사용하며 새 Student·University·Major 생성이나 수동 학교·학과 입력은 지원하지 않는다.
- Student 또는 Major 후보가 확정되지 않으면 생성 버튼을 비활성화하고 사용자가 기존 후보를 선택하게 한다.
- 회차와 언어 변경은 이미 읽어 온 Student·Major 선택을 유지한 채 생성 제목과 Category에 즉시 반영한다. 실제 생성 직전 서버 preflight에서 현재 후보 관계를 다시 검증한다.
- 첨부파일 다운로드와 학생명 접두 파일명 변경은 계획대로 Phase SOP-6으로 남겨 이번 구현에 포함하지 않았다.

## Current Status - SOP 감수 요청 자동화 구현

- VBS가 Windows PowerShell의 절대 경로와 프로젝트 작업 폴더를 사용하고, 런처 완료까지 기다리도록 보강했다.
- 잘못된 바탕화면 바로가기 대상을 검증된 PowerShell 런처로 교체했다. 바탕화면 표시 이름은 기존 `Admission Helper.vbs`를 유지했다.
- 기존 3000번 서버를 한 번 종료한 뒤 수정된 실행 경로로 재시작해 SOP 화면이 제공되는지 확인했다.

## Decisions - 로컬 실행 바로가기 및 서버 재시작 보정

- 포트만 보고 임의 프로세스를 종료하지 않는다. 실행 스크립트가 기록한 PID가 현재 `node` 프로세스일 때만 재시작한다.
- PID 기록이 없는 기존 서버는 자동 종료하지 않고 기존 동작대로 앱만 연다. 이번에 남아 있던 구버전 서버는 PID와 앱 응답을 직접 확인한 뒤 한 번만 수동 교체한다.
- Windows Script Host가 이 PC에서 리소스 오류로 VBS를 실행하지 못해, 바탕화면 바로가기는 VBS를 거치지 않고 PowerShell 런처를 직접 호출한다.
