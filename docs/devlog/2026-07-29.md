## Decisions

- 학부 문서의 빈도가 매우 낮아 자동 과정 판별의 복잡성과 오판 가능성을 감수할 필요가 없다고 판단했다.
- Notion만 등록하는 날과 Word만 만드는 날을 모두 지원하기 위해 두 실행 버튼과 실행 조건을 독립시켰다. Notion 생성 성공 여부는 Word 생성 조건으로 사용하지 않는다.
- Word 전공명은 Notion 쓰기 결과가 아니라 검토 화면에서 확정된 Notion용 이름을 사용한다. 기존 항목이 매칭되면 실제 기존 이름을, 신규 후보이면 검토·확정한 생성 예정 이름을 사용한다.
- 머리말의 학부 표기는 `[학부]`가 아니라 `[학사]`로 확정했다.
- 미세한 줄간격 차이를 막기 위해 문단·표를 재생성하지 않고 템플릿 OOXML을 복제한 뒤 텍스트 노드만 치환하도록 계획했다.

## Work Summary - Notion·Word 확인 단계 단축

자동화 앱에서 기술 상태 확인을 위해 사용자가 반복해서 버튼을 누르는 흐름이 과도하다는 피드백을 반영했다. 기계가 판단할 수 있는 Notion 스키마와 Word 템플릿 검사는 내부에서 자동 실행하고, 사용자의 업무 판단 또는 실제 실행에 필요한 버튼만 남겼다.

## Work Completed - Notion·Word 확인 단계 단축

- 별도 `연결 및 스키마 확인` 버튼을 제거했다.
- `Notion 항목 확인` 한 번으로 연결·스키마 검사와 읽기 전용 항목 조회가 순서대로 실행되도록 통합했다.
- 스키마 검사가 실패하면 항목 조회를 실행하지 않고 연결 상태와 해결 안내를 표시하도록 했다.
- 별도 `템플릿 상태 확인` 버튼을 제거했다. Word 섹션이 열릴 때 템플릿·출력 폴더 상태를 자동 검사하는 기존 동작을 기본 흐름으로 사용했다.
- 별도 `Word 내용 요약 확인` 버튼과 Word 생성 직전의 중복 확인창을 제거했다.
- 최종 학생명, 과정, Programme Label, 전공명, URL, 파일명을 `Word 생성 예정 내용`으로 자동 표시하고 입력 변경 시 즉시 갱신하도록 했다.
- Word 필수 입력과 템플릿 상태가 정상일 때 `Word 파일 만들기` 버튼 하나로 즉시 새 DOCX를 생성하도록 단축했다. 기존 파일을 덮어쓰지 않는 번호 저장 규칙은 유지했다.
- README와 Phase 5 계획 문서의 사용 흐름을 새 동작에 맞게 갱신했다.
- 정적 화면 테스트에 제거된 세 확인 버튼이 다시 나타나지 않는 회귀 검사를 추가했다.

## Decisions - Notion·Word 확인 단계 단축

- Notion은 외부 데이터 생성이며 여러 페이지 생성에 트랜잭션이 없으므로 `Notion 항목 확인`과 최종 `Notion에 기록 생성`은 분리해 유지했다.
- Notion 스키마 검사와 Word 템플릿 검사는 사용자 판단이 필요 없는 기술 점검이므로 별도 버튼이 아니라 각 실행 흐름의 자동 사전 검사로 처리했다.
- Word 파일은 기존 파일을 덮어쓰지 않고 새 번호로 저장되므로 별도 요약 승인과 브라우저 확인창을 중복으로 요구하지 않기로 했다.
