## Work Summary - 라벨형 요청과 URL 학위명 보완

담당자가 `학교:`, `전공:`, `학과:` 라벨을 섞어 쓰고 학위명은 생략한 새 JANDI 요청 형식을 반영했다. 기존 파서는 라벨 왼쪽을 대학명으로 오인해 가짜 URL 누락 경고를 만들었고, 학과명에 학위가 없으면 Notion 생성 후보에도 학위를 보완하지 못했다. 제공된 실제 형식을 회귀 입력으로 고정하고 URL에서 명시적으로 확인되는 학위만 안전하게 보완하도록 변경했다.

## Work Completed - 라벨형 요청과 URL 학위명 보완

- 일반 콜론 구분 규칙보다 먼저 `학교:`를 대학 필드로, `전공:`과 `학과:`를 같은 학과 필드로 해석하도록 파서를 보완했다.
- 학과명에 학위가 없고 과정 URL 경로에 `msc`, `ma`처럼 인식 가능한 학위 토큰이 하나만 있으면 Notion 학과 후보명 맨 뒤에 정규화된 학위명을 붙이도록 했다.
- 담당자가 작성한 `programmeNameOriginal`은 변경하지 않고 URL에서 보완한 값은 파생 필드와 화면 안내로 구분했다.
- 이름과 URL의 학위 충돌, URL의 복수 학위, 양쪽 모두 학위 없음은 자동 확정하지 않고 수동 검토 상태로 표시했다.
- URL 쿼리 문자열과 다른 단어 안의 부분 문자열은 학위 근거로 사용하지 않도록 제한했다.
- Liverpool, Cardiff, Aston의 새 요청 형식과 NBSP 공백·Markdown 링크를 포함한 서버 회귀 테스트를 추가했다.
- 화면에서 URL 기반 자동 보완과 충돌·복수·누락 검토 사유를 구분해 표시하도록 했다.
- 프로젝트 명세에 URL 학위 보완의 허용 범위와 수동 검토 경계를 기록했다.

## Decisions - 라벨형 요청과 URL 학위명 보완

- 담당자가 학위명을 쓰지 않았다고 무조건 `MSc`를 붙이지 않는다. 공식 과정 URL 경로의 독립된 학위 토큰이 하나일 때만 보조 근거로 사용한다.
- 담당자 입력에 정상 학위명 또는 기존 허용 오타 `MCs`가 있으면 이름을 우선하되, URL과 충돌하면 조용히 덮어쓰지 않고 검토 대상으로 남긴다.
- URL에서 전체 학과명을 추측하지 않고 학위 토큰만 보완한다. 기존의 원문 보존과 도메인 우선 대학 판별 원칙은 유지한다.
