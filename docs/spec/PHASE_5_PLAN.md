# Phase 5 Word 자동 생성 계획

- 작성일: 2026-07-29
- 대상 프로젝트: Admission Guidelines Automation
- 상태: 구현 전 계획 확정
- 선행 단계: Phase 4 테스트 계속 진행 중

## 1. 목표

검토가 완료된 입학요강 요청을 기준으로 기존 Word 템플릿의 서식과 레이아웃을 보존한 DOCX 파일을 자동 생성한다.

생성 문서는 전공별로 다음 단위를 반복한다.

```text
학교명
전공명
URL

입학요강 표
```

SOP 글자 수 환산표와 관련 참고 내용은 문서 마지막에 한 번만 유지한다.

## 2. 구현 원칙

### 2.1 Phase 4와 분리

- Phase 4 테스트가 계속되는 동안 Phase 5 구현을 시작할 수 있다.
- Phase 5 기능은 feature flag로 분리하고, 서식 동일성 검증 전에는 일반 사용을 활성화하지 않는다.
- Phase 4의 Notion 생성·복구 흐름을 변경하지 않는다.
- Word 생성은 Notion 쓰기 작업과 독립된 기능으로 구현하고, 공통 검토 화면의 확정값을 입력으로 사용한다.

### 2.2 Notion과 Word 버튼 분리

UI에는 서로 다른 작업 버튼을 둔다.

1. `Notion에 기록 생성`
2. `Word 파일 만들기`

두 버튼은 각각 독립적으로 실행할 수 있다.

- Notion 등록만 필요한 경우에는 Word 파일을 만들지 않고 작업을 끝낼 수 있다.
- Word 파일만 필요한 경우에는 Notion에 페이지를 생성하지 않고 Word 파일을 만들 수 있다.
- 두 작업이 모두 필요한 경우에는 각 버튼을 필요한 순서대로 실행할 수 있다.
- `Word 파일 만들기`는 Notion 생성 성공 여부가 아니라 Word에 필요한 입력값의 검토·확정 여부로 활성화한다.
- 입력값이 변경되면 Notion 미리보기·생성 계획은 다시 확인하게 하고, Word 생성 예정 요약은 현재 확정값으로 자동 갱신한다.
- 같은 요청에서 Word를 다시 만들면 기존 파일을 덮어쓰지 않고 새 번호로 저장한다.

## 3. 과정 구분

학부 요청은 매우 드물기 때문에 학부·석사 자동 판별 로직은 구현하지 않는다.

Word 생성 영역에 간단한 과정 선택 항목을 둔다.

- 기본값: `석사`
- 선택 가능 값: `석사`, `학사`
- 머리말 출력: `[석사]` 또는 `[학사]`

이 선택은 Word 머리말에만 사용한다. Notion 등록은 기존 전공명 학위 표기와 Major 매칭 규칙을 그대로 사용하므로 과정 선택을 요구하지 않는다.

## 4. 전용 템플릿

전용 원본 파일:

```text
C:\Users\Marion\Documents\Custom Office Templates\[2026입학요강] 자동생성용.docx
```

원본 템플릿은 읽기 전용 원본처럼 취급한다. 생성할 때마다 템플릿을 복사하고 복사본의 필요한 XML만 수정한다.

현재 내용이 계속 바뀌는 다음 파일은 자동 생성 원본으로 사용하지 않는다.

```text
C:\Users\Marion\Documents\EDM\[2026입학요강] Template.docx
```

### 4.1 머리말 마커

템플릿 머리말에는 다음 문자열을 정확히 입력한다. 마커는 대괄호를 두 겹 모두 사용한다.

```text
[[DEGREE_PREFIX]] [[PROGRAMME_LABEL]]
[[STUDENT_NAME]]님
```

치환 예:

```text
[[DEGREE_PREFIX]]  -> [석사]
[[PROGRAMME_LABEL]] -> Nutrition
[[STUDENT_NAME]]    -> 김윤지
```

최종 출력:

```text
[석사] Nutrition
김윤지님
```

마커가 있는 문단과 글자 조각에는 최종 결과에서 원하는 글꼴, 크기, 굵기, 줄간격, 문단 간격을 미리 적용해 둔다.

### 4.2 본문 프로토타입 블록

템플릿 본문에는 다음 순서의 전공 1개분 프로토타입을 둔다.

```text
[[UNIVERSITY]]
[[PROGRAMME]]
[[URL]]

입학요강 표 1개

```

그 뒤에는 고정 영역을 둔다.

- `SOP 글자 수 환산표` 제목
- 참고 표 1개
- 기존 참고 문구

## 5. Word 입력값

### 5.1 머리말

| 위치 | 입력값 |
|---|---|
| 과정 | Word 생성 영역에서 선택한 `석사` 또는 `학사` |
| 대표 전공명 | 검토 화면의 Programme Label |
| 학생명 | 검토 화면에서 확정된 최종 학생명 |

### 5.2 전공별 본문

| 항목 | 입력값 | 규칙 |
|---|---|---|
| 학교명 | 담당자 원문의 학교명 | 별도 미화나 `2026/27 entry` 추가 없이 그대로 사용 |
| 전공명 | 검토 화면에서 확정된 Notion용 Major 이름 | 기존 Major가 매칭되면 기존 Notion 이름, 새 Major 후보이면 검토·확정한 생성 예정 이름 |
| URL | 담당자 원문의 URL | 보이는 문자열을 그대로 유지하면서 클릭 가능한 외부 하이퍼링크로 생성 |

전공명은 더 이상 `programmeNameOriginal`을 직접 사용하지 않는다. Notion 쓰기 실행 여부와 관계없이 검토 화면에서 확정된 Notion용 Major 이름을 해당 원문 전공과 연결하여 사용한다.

학생명과 전공명은 다음 우선순위로 정한다.

1. 기존 Notion 항목이 매칭된 경우 해당 항목의 실제 이름
2. 새 항목 후보인 경우 사용자가 검토·확정한 생성 예정 이름

따라서 Word만 만드는 날에도 Notion 페이지를 새로 생성할 필요가 없다.

## 6. DOCX 생성 방식

DOCX를 새로 조립하거나 Word 객체 모델에서 표와 문단을 다시 만들지 않는다.

1. 전용 템플릿 DOCX를 작업용 파일로 복사한다.
2. DOCX ZIP 패키지에서 필요한 XML만 연다.
3. `word/header1.xml`의 마커 텍스트 노드만 치환한다.
4. `word/document.xml`에서 프로토타입 블록 전체를 전공 수만큼 복제한다.
5. 각 복제 블록에서 학교명과 최종 Notion 전공명을 치환하고, 전공명 run에는 굵기를 적용한다.
6. URL 마커는 보이는 원문 URL을 유지한 외부 하이퍼링크로 치환하고 `word/_rels/document.xml.rels`에 고유 관계를 추가한다.
7. 입학요강 표는 표 전체 XML을 복제한다.
8. SOP·참고 영역은 한 번만 남긴다.
9. 수정한 패키지를 임시 파일에 완성한 뒤 최종 위치로 원자적으로 이동한다.

다음 요소는 재생성하거나 정규화하지 않는다.

- 문단 속성
- 글자 속성
- 줄간격과 문단 간격
- 표 셀 여백과 높이
- 스타일, 번호 매기기, 테마
- section, header, footer 관계
- Enter와 Shift+Enter의 구분

URL은 `document.xml`의 `w:hyperlink` 요소와 `document.xml.rels`의 외부 관계를 함께 생성한다.

## 7. 템플릿 검증

서버 시작 또는 Word 상태 확인 시 다음을 검증한다.

- 템플릿 파일 존재
- 허용된 DOCX 형식
- 등록된 SHA-256과 실제 파일 일치
- 머리말 마커 3개 존재
- 본문 마커 3개 존재
- 복제 대상 입학요강 표 1개 존재
- 고정 SOP·참고 영역 존재
- 마커 중복이나 누락 없음

검증에 실패하면 Notion 기능은 계속 사용할 수 있지만 Word 생성 버튼은 비활성화하고 원인을 표시한다.

## 9. API 계획

### 9.1 상태 확인

```text
GET /api/word/status
```

응답 내용:

- 기능 활성화 여부
- 템플릿 존재 여부
- 템플릿 구조 검증 결과
- 출력 폴더 사용 가능 여부
- 오류 코드와 사용자용 설명

### 9.2 파일 생성

```text
POST /api/word/generate
```

주요 요청값:

- 검토 화면에서 확정된 최종 학생명
- 과정 선택값: `석사` 또는 `학사`
- 검토 가능한 Word 파일명
- Programme Label
- 전공별 원문 학교명
- 전공별 검토·확정된 Notion용 Major 이름
- 전공별 원문 URL

서버는 Notion 생성 journal이나 완료 fingerprint를 Word 생성 조건으로 요구하지 않는다. 대신 Word 요청값, 과정 선택값, 파일명, 템플릿 상태와 출력 경로를 독립적으로 검증한다.

## 10. 저장 규칙

저장 위치:

```text
C:\Users\Marion\Desktop
```

기본 파일명:

```text
[2026입학요강] 학생명님_Programme Label.docx
```

저장 규칙:

- 기존 파일을 덮어쓰지 않는다.
- 같은 파일명이 있으면 `(2)`, `(3)`을 붙인다.
- 경로 구분자와 Windows 금지 문자를 제거한다.
- 상대 경로와 path traversal을 거부한다.
- 같은 Desktop 위치에 `학생명_Programme Label` 작업 폴더를 생성하거나 기존 폴더를 재사용한다.
- Word 파일은 작업 폴더 안으로 이동하지 않고 기존과 같이 Desktop에 직접 저장한다.
- 저장 후 Word를 자동으로 열지 않는다.
- ZIP 파일은 만들지 않는다.

## 11. UI 흐름

```text
JANDI 요청 추출
→ 원문 및 Notion 전공명 검토
→ 필요한 작업 선택
   ├─ Notion 미리보기 → Notion에 기록 생성
   └─ Word 과정 선택 확인 → 생성 예정 내용 자동 요약 → Word 파일 만들기
```

- Notion만 필요한 날에는 Notion 경로만 실행한다.
- Word만 필요한 날에는 Word 경로만 실행한다.
- 둘 다 필요한 날에는 두 경로를 모두 실행하며 순서를 강제하지 않는다.

자동 Word 생성 예정 요약에는 다음을 표시한다.

- 최종 학생명
- `[석사]` 또는 `[학사]`
- Programme Label
- 전공 수
- 학교명 / 검토된 Notion용 전공명 / URL 목록
- 최종 저장 예정 파일명

## 12. 테스트 계획

### 12.1 템플릿 검증

- 템플릿 없음
- SHA-256 불일치
- 머리말 마커 누락·중복
- 본문 마커 누락·중복
- 입학요강 표 누락
- SOP·참고 영역 누락

### 12.2 생성 결과

- 전공 1개, 3개, 5개
- 각 전공마다 학교명·전공명·URL·입학요강 표가 한 번씩 존재
- SOP·참고 표는 항상 한 번만 존재
- 과정 기본값 `[석사]`
- 과정 변경 시 `[학사]`
- 검토·확정된 Notion용 Major 이름 사용
- 원문 학교명과 URL 보존
- 전공명 bold run 생성
- URL별 고유 hyperlink relationship 생성
- XML 특수문자와 긴 URL 처리

### 12.3 서식 보존

- 머리말 문단 간격과 줄간격 유지
- 표 안의 `Normal`·`ListParagraph` 구조 유지
- 글꼴, 크기, 굵기, 밑줄 등 직접 서식 유지
- 표 구조, 셀 속성, 행 높이 유지
- 수정 대상이 아닌 DOCX package part의 해시 유지
- Enter와 Shift+Enter 구조 유지

### 12.4 독립 실행과 동작 Gate

- Notion을 생성하지 않은 상태에서 Word만 정상 생성
- Notion 생성 실패·부분 실패 뒤에도 Word 입력 검토가 완료되면 Word 생성 가능
- Word를 만들지 않고 Notion만 정상 생성
- 두 기능을 순서와 관계없이 각각 실행
- Word 필수 입력이 미확정이면 Word 생성만 차단
- 입력 변경 후 Word 생성 예정 요약 자동 갱신
- feature flag 비활성화 시 Word 생성 차단
- 파일명 충돌 시 `(2)`, `(3)` 저장

### 12.5 최종 검증

1. 기존 전체 자동 테스트를 다시 실행한다.
2. 전공 1개 샘플 DOCX를 생성한다.
3. Microsoft Word에서 전용 템플릿과 생성 결과를 전체 페이지 단위로 비교한다.
4. 머리말 줄간격, 본문 줄간격, 표 내부 문단 간격, 페이지 나눔을 확인한다.
5. 전공 3개 샘플에서 반복 순서와 참고 표 1회 유지를 확인한다.
6. J님의 서식 승인 후에만 `WORD_GENERATION_ENABLED=true`로 전환한다.

## 13. 구현 범위 제외

Phase 5에서 다음은 구현하지 않는다.

- 입학요강 표 내용 자동 조사·입력
- 학부·석사 자동 판별
- 담당자 원문 학교명 미화
- URL 자동 수정
- PDF 결과물 제공
- ZIP 묶음 생성
- Word 자동 실행
- 기존 Notion 페이지 자동 수정·삭제

## 14. 완료 기준

다음을 모두 만족하면 Phase 5를 완료로 본다.

1. Notion 버튼과 Word 버튼이 서로 독립적으로 동작한다.
2. Notion만 처리하거나 Word만 만들거나 두 작업을 모두 실행할 수 있다.
3. Word 과정 기본값은 석사이며 예외적으로 학사를 선택할 수 있다.
4. 머리말이 `[석사] Programme Label` 또는 `[학사] Programme Label`로 생성된다.
5. 학생명은 검토 화면에서 확정된 최종 학생명을 사용한다.
6. 학교명과 URL은 담당자 원문을 유지한다.
7. 전공명은 검토 화면에서 확정된 Notion용 Major 이름을 사용한다.
8. 전공별 입학요강 표가 전체 XML 복제로 생성된다.
9. SOP·참고 표는 문서에 한 번만 존재한다.
10. 기존 파일을 덮어쓰지 않고 Desktop에 저장한다.
11. 같은 Desktop 위치에 `학생명_Programme Label` 작업 폴더를 생성하거나 재사용한다.
12. 생성 후 Word를 자동으로 열지 않는다.
13. Microsoft Word 비교에서 머리말·본문·표의 미세 서식 차이가 승인 범위 안에 있다.
